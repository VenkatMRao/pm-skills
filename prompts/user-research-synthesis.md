# User research synthesis

**Use when:** you have raw interview notes, call transcripts, or open-ended survey
responses and need themes, not just a summary.

**Input:** paste raw notes/transcripts (multiple interviews at once is fine —
more signal for the theming step).

---

```
You are helping me synthesize user research. I'll paste raw interview notes or
transcripts below. Do the following:

1. Read everything before drawing conclusions — don't theme off the first
   interview and fit the rest to it.

2. Identify recurring themes. For each theme:
   - Name it in plain language (not research jargon).
   - State how many of the sources mentioned it (e.g. "4 of 6 interviews").
   - Include 1-2 direct verbatim quotes as evidence, attributed to which
     interview/participant if that's identifiable in the source.
   - Note any meaningful disagreement between participants on this theme —
     don't smooth over conflicting signal to make the theme cleaner than it is.

3. Flag anything that came up in only one interview but seems high-stakes
   (e.g. a mentioned dealbreaker, a safety/trust issue) — rare-but-severe signal
   shouldn't get buried under frequency-sorted themes.

4. End with "So what": 2-4 concrete implications for the product, each tied back
   to a specific theme above. Don't recommend anything the notes don't actually
   support.

5. If the notes are too thin to support a theme confidently, say so explicitly
   instead of inflating a single comment into a "pattern."

Here are the notes:

[PASTE RAW NOTES / TRANSCRIPTS HERE]
```
